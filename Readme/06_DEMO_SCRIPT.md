# VERICARB Demo Script (3–5 minutes)

## Opening (20 seconds)
“VERICARB is a continuous carbon-integrity network. It tracks a credit’s provenance, checks for registry conflicts, and monitors new evidence that could affect the integrity of the underlying climate outcome.”

Show the overview dashboard and the visible “DEMO ENVIRONMENT — NOT CERTIFIED CARBON CREDITS” notice.

## Project passport (35 seconds)
Open the fictional forest project. Show project identity, location/region, methodology, vintage, registry reference, evidence items, and the event timeline. Emphasize that raw files remain off-chain while evidence hashes can be anchored on-chain.

## AI evidence review (40 seconds)
Open the evidence review page. Show a missing verification report or inconsistent quantity. Explain that AI flags issues for a human reviewer and does not certify credits.

## Double-Claim Firewall (35 seconds)
Import the sample registry CSV. Show a duplicate serial/reference conflict with the exact matching fields. Explain that this check covers imported records only; it is not a global guarantee across every registry.

## Lifecycle and blockchain (40 seconds)
Show reviewer approval, then register/issue a batch if a working local/testnet chain is configured. Open the actual transaction receipt. Retire a small portion and show the append-only retirement event. If only local Hardhat is configured, label it local.

## Reversal Oracle (45 seconds)
Trigger the clearly marked synthetic forest-disturbance event. Show the AT_RISK alert and the integrity score component that changed. Have a reviewer confirm or reject the alert. Show that the history records the decision and does not delete the earlier retirement event.

## Public verification (25 seconds)
Open the public verification page. Show credit ID, score breakdown, source coverage, evidence hashes, lifecycle timeline, alerts, and transaction links if available.

## Close (15 seconds)
“VERICARB does not replace independent verification or official registries. It provides a transparent integrity layer that helps people inspect evidence, detect conflicts, and track changes over time.”

## Presenter checklist
- Verify demo data labels are visible.
- Use only real tx hashes from confirmed receipts.
- If live integrations are unavailable, disclose which elements are simulated.
- Do not say the credits are certified or that all cross-registry duplication is prevented.
- Keep the demo to one clear project and one clear alert.
